This post walks through building cafeai-support — a technical support assistant for an open source Java library called Helios — using CafeAI as the underlying framework. We start with an empty directory and end with a tested, observable, production-shaped application. Every phase adds exactly one layer, tested before moving on.

CafeAI follows the Express.js middleware model but is built entirely in Java 21 on Helidon SE. If you know Express, the API will feel immediately familiar. If you don't, the pattern is simple: register middleware and route handlers on an app object, then listen on a port.

Before you start: Publish CafeAI to your local Maven repository from the CafeAI root: ./gradlew publishToMavenLocal. Verify Java 21+ with java -version. Run this command again whenever you change the framework.

PHASE 02 Plain HTTP Server
Goal: A working HTTP server with structured JSON, request logging, and proper error handling — before any AI touches it.

Always establish a working HTTP baseline before adding AI. If something breaks later, you'll know it's the AI layer, not the HTTP layer.

SupportAgent.java — complete replacement
package io.cafeai.support;

import io.cafeai.core.CafeAI;
import io.cafeai.core.middleware.Middleware;
import java.util.Map;

public class SupportAgent {

    public static void main(String[] args) {
        var app = CafeAI.create();

        app.filter(Middleware.requestLogger());
        app.filter(CafeAI.json());

        app.get("/health", (req, res, next) ->
            res.json(Map.of("status", "ok", "service", "cafeai-support")));

        app.post("/support", (req, res, next) -> {
            String message = req.body("message");
            if (message == null || message.isBlank()) {
                res.status(400).json(Map.of("error", "Field 'message' is required"));
                return;
            }
            res.json(Map.of(
                "question", message,
                "response", "Echo (AI not yet connected): " + message
            ));
        });

        app.listen(8080);
    }
}

PHASE 05 GitHub Tools
Goal: Give the LLM the ability to look up live data that isn't in the knowledge base. Issue status changes daily — RAG can't help with that.

implementation 'io.cafeai:cafeai-tools:0.1.0-SNAPSHOT'

src/main/java/io/cafeai/support/GitHubTools.java
package io.cafeai.support;

import io.cafeai.tools.CafeAITool;

public class GitHubTools {

    @CafeAITool("Fetch the current status of a Helios GitHub issue by its number.")
    public String getIssueStatus(String issueNumber) {
        return switch (issueNumber.trim()) {
            case "142" -> "Issue #142: Connection leak — CLOSED, fixed in v2.1.0";
            case "156" -> "Issue #156: maxLifetime not honoured on DB restart — OPEN. Workaround: set keepaliveTime=30000";
            case "189" -> "Issue #189: leakDetectionThreshold false positives — OPEN";
            default    -> "Issue #" + issueNumber + " not found";
        };
    }

    @CafeAITool("Search open Helios issues by keyword.")
    public String searchIssues(String keyword) {
        String lower = keyword.toLowerCase();
        if (lower.contains("timeout") || lower.contains("connection"))
            return "Found: #156 (maxLifetime), #189 (leakDetection)";
        return "No open issues matching '" + keyword + "'";
    }

    @CafeAITool("Get the latest Helios release version and changelog.")
    public String getLatestRelease() {
        return "Helios v2.1.0 (2026-02-14): Fixed #142 connection leak, +23% performance, virtual thread support";
    }
}

PHASE 07 Guardrails
Goal: Make the assistant safe and on-topic. Guardrails are middleware — they run before every request reaches the LLM.

implementation 'io.cafeai:cafeai-guardrails:0.1.0-SNAPSHOT'

SupportAgent.java — guardrail registrations (before app.filter())
import io.cafeai.core.guardrails.GuardRail;

// Block prompt injection in user input and RAG documents
app.guard(GuardRail.promptInjection());

// Block adversarial prompts trying to hijack the assistant
app.guard(GuardRail.jailbreak());

// Keep conversations on-topic — Helios support only
app.guard(GuardRail.topicBoundary()
    .allow("helios", "connection", "pool", "jdbc", "database",
           "timeout", "configuration", "error", "exception",
           "driver", "postgresql", "mysql", "spring", "upgrade",
           "version", "release", "issue", "bug", "fix", "install",
           "dependency", "gradle", "maven", "thread", "virtual",
           "idle", "active", "leak", "keepalive", "lifetime",
           "credential", "url", "username", "password"));
Topic boundary tuning: The allow list is keyword-based and stateless. Keep follow-up questions Helios-specific: "Which Helios configuration property should I check?" passes; "What should I check?" does not. This is correct behaviour — write test messages that include topic keywords.

PHASE 10 WebSocket Streaming Chat
Goal: Real-time bidirectional chat on the same port as HTTP. The full AI stack — RAG, memory, tools, guardrails — all available over WebSocket.

No new dependency. WebSocket is in cafeai-core. Helidon upgrades WebSocket handshakes automatically on the same port.

SupportAgent.java — WebSocket handler (after POST /support route)
import io.cafeai.core.routing.WsHandler;
import io.cafeai.core.routing.WsSession;
import java.util.Set;
import java.util.concurrent.ConcurrentHashMap;

Set<WsSession> activeSessions = ConcurrentHashMap.newKeySet();

app.ws("/ws/support", new WsHandler() {

    @Override
    public void onOpen(WsSession session) {
        activeSessions.add(session);
        session.send("""
            {"type":"connected","message":"Helios support ready. How can I help?"}""");
    }

    @Override
    public void onMessage(WsSession session, String message) {
        // Virtual thread — don't block the WebSocket thread
        Thread.ofVirtual().start(() -> {
            try {
                var response = app.prompt(message)
                                  .session(session.id())
                                  .call();
                session.send("""
                    {"type":"response","answer":"""
                    + jsonStr(response.text()) + ","
                    + "\"sources\":" + response.ragDocuments().size() + "}");
            } catch (Exception e) {
                session.send("{\"type\":\"error\",\"message\":"
                    + jsonStr(e.getMessage()) + "}");
            }
        });
    }

    @Override
    public void onClose(WsSession session, int code, String reason) {
        activeSessions.remove(session);
    }

    @Override
    public void onError(WsSession session, Throwable error) {
        activeSessions.remove(session);
    }

    private String jsonStr(String s) {
        if (s == null) return "\"\"";
        return "\"" + s.replace("\\", "\\\\")
                      .replace("\"", "\\\"")
                      .replace("\n", "\\n") + "\"";
    }
});

Summary

Here is every layer of the finished application — what it adds, which CafeAI module it comes from, and what it costs in terms of new dependencies:

Phase What it adds Module Key API
1 — Scaffold Gradle project, logback config, empty main class cafeai-core —
2 — HTTP JSON middleware, health endpoint, support endpoint with validation cafeai-core app.filter() app.get() app.post()
3 — AI Provider Ollama with OpenAI fallback, system prompt, first LLM call cafeai-connect app.connect() app.system() app.prompt()
4 — RAG Knowledge base ingestion, semantic retrieval, console observability cafeai-rag cafeai-observability app.vectordb() app.embed() app.rag() app.ingest() app.observe()
5 — Tools GitHub issue lookup, search, release notes via @CafeAITool cafeai-tools app.tool() @CafeAITool
6 — Memory Per-session conversation history, session isolation cafeai-memory app.memory() MemoryStrategy.inMemory()
7 — Guardrails Topic boundary, jailbreak detection, prompt injection blocking cafeai-guardrails app.guard() GuardRail.topicBoundary() GuardRail.jailbreak()
8 — Observability Per-call traces: model, tokens, latency, RAG docs retrieved cafeai-observability ObserveStrategy.console()
9 — Security Stricter injection detection, typed audit events with unique IDs cafeai-security AiSecurity.promptInjectionDetector() AiSecurity.onEvent()
10 — WebSocket Streaming chat on same port, virtual thread per message, full AI stack cafeai-core app.ws() WsHandler WsSession
11 — Polish README, docker-compose, automated test script — 9/9 tests passing

What this demonstrates about CafeAI

Each feature is independently opt-in. Add cafeai-memory to the classpath and app.memory() to your startup — that's the entire cost of adding session memory. Remove the JAR and the application falls back gracefully. No configuration files, no annotations to hunt down, no XML.

The HTTP layer and the AI layer compose cleanly. Guardrails are middleware. The security filter is middleware. They sit in the same pipeline as your request logger and JSON parser. There is one composition model in the entire framework.

Every request carries its full context automatically. Once you wire RAG, memory, tools, and guardrails at startup, app.prompt(message).session(id).call() does everything. The handler doesn't know about vector stores or tool dispatch. It asks a question and gets an answer.

Fallback is a first-class concept. Ollama unavailable → OpenAI activates. Redis unavailable → in-memory activates. The application starts either way. This is not accident tolerance, it's deliberate design.
